EXECUTIVE SUMMARY
-----------------
The project follows some solid foundations (TypeScript strict mode, App Router,
shadcn-style UI primitives, ESLint with eslint-config-next). It is still early /
WIP in many areas: placeholder copy, incomplete sections, inconsistent component
patterns, and no tests or CI. Lint currently fails (1 error, 5 warnings). Treat
`components/ui/*` as the quality bar; most of `app/components/*` has not reached
that bar yet.

Overall verdict: PARTIAL best practices — good scaffolding, uneven application.


================================================================================
WHAT IS DONE WELL
================================================================================

1. TypeScript
   - tsconfig.json: strict: true, bundler moduleResolution, path alias @/*
   - UI primitives use proper typing (VariantProps, ComponentProps, etc.)

2. Next.js structure
   - App Router: app/layout.tsx, app/page.tsx, colocated app/components/
   - next/font for Geist, Geist Mono, Poppins in layout.tsx
   - next/image used in most image-heavy sections (Services, AboutUs, Banner)

3. Styling system
   - Tailwind CSS v4 + shadcn theme tokens in globals.css
   - Brand CSS variables (--red, --gray, --yellow) and reusable .wContainer
   - cva + class-variance-authority on Button (shadcn pattern)

4. UI layer
   - components/ui/button.tsx, card.tsx, carousel.tsx — structured, reusable
   - carousel.tsx: context hook, ARIA on prev/next, sr-only labels (good a11y
     pattern for that widget)

5. Client/server split (partial)
   - Services.tsx correctly uses "use client" for carousel state (useState + api)

6. ESLint
   - eslint.config.mjs uses eslint-config-next core-web-vitals + typescript

A) Lint / quality gate (current state)

     (setState via onSelect inside useEffect; shadcn boilerplate vs stricter

     * app/components/Hero.tsx — Image

   Recommendation: Fix warnings; resolve carousel effect pattern so CI lint passes.
   Add script: "lint": "eslint ." (already default) and run lint in CI.

B) No automated tests
   - No vitest/jest, no @testing-library/react, no test files
   - No .github/workflows or other CI

   Recommendation: Vitest + RTL smoke tests for layout/page; CI: npm ci, lint,
   typecheck, build, test.

C) No formatter or pre-commit enforcement
   - No Prettier, no husky/lint-staged
   - Inconsistent style: 4-space indent in app/components vs 2-space in
     components/ui; mixed quote styles in className ('bg-(--red)' vs "lg")

D) Placeholder / broken UI content (production readiness)
   - app/components/Footer.tsx — literal "dsddsa"
   - app/components/Review.tsx — "sda" in reviews column; Comment.tsx empty
   - app/components/Comment.tsx — commented Image stub, empty <h1></h1>
   - app/layout.tsx metadata still "Create Next App" / "Generated by create next app"

E) Accessibility & semantics
   - app/components/Header.tsx:
     * Nav items are <li> text only — not links; no keyboard focus, no href
     * Icon-only areas (user, cart) are <span> — need button + aria-label
     * Image height={0} with width={210} — invalid for next/image aspect ratio
   - Multiple <h1> on one page (Services, CardComp, Carousel1, AboutUs, Review,
     Comment) — SEO/a11y: one h1 per page, section titles as h2/h3
   - app/components/Services.tsx: both carousel buttons aria-label="Go Back";
     second should be "Go forward" or similar
   - Star ratings: decorative stars should be aria-hidden; expose rating in text
     (Review partially does via "5.0 out of 5")
   - app/components/Hero.tsx: floating chat uses @base-ui Button with no
     aria-label

//F) Inconsistent Button usage
   - Most files: @/components/ui/button (styled, variants, focus rings)
   - app/components/Hero.tsx: Button from @base-ui/react directly — skips
     design system and shared a11y styles

   Recommendation: Single import path for all buttons.


================================================================================
MEDIUM PRIORITY — CODE STRUCTURE & MAINTAINABILITY
================================================================================

//G) Export / naming conventions
   - Footer: named export `export function Footer`
   - All other section components: default export
   - Carousel1.tsx — non-descriptive name (prefer TeamGallery, GalleryCarousel)

   Recommendation: Pick one pattern (default exports for pages/sections or named
   for all) and rename opaque components.

//H) Data vs presentation
   - app/components/CardComp.tsx stores React elements in data array
     ({ img: <TbReceipt2 /> }) — harder to test/serialize; prefer icon component
     type or icon name string + map to component
   - Carousel content arrays live inside components — fine for now; extract to
     lib/content/*.ts when copy stabilizes for i18n and non-dev edits

I) React list keys
   - index used as key in: Comment, CardComp, Services, Carousel1, Review
   - Static lists: acceptable; prefer stable id/slug keys (e.g. carousel image
     filename as key in Carousel1)

//J) Dead / commented code
   - Comment.tsx, Carousel1.tsx — large commented blocks
   - Carousel1.tsx — commented setApi / overlay markup

   Recommendation: Remove or finish; use git history instead of comment dumps.

K) lib/utils.ts vs direct "cn" imports
   - lib/utils.ts: export { cn } from "cn"
   - components/ui/button.tsx, carousel.tsx import cn from "cn" directly
   - package.json lists "cn" as dependency (not clsx + tailwind-merge classic
     shadcn setup)

   Recommendation: Import cn only from @/lib/utils for one indirection; confirm
   "cn" package is intentional (vs clsx/tailwind-merge).

//L) Unused font loading
   - layout loads Geist + Geist Mono + Poppins; body uses font-poppins only
   - Geist variables applied on <html> but primary UI font is Poppins

   Recommendation: Drop unused fonts or apply Geist where intended (reduces
   layout shift / build font fetches).

//M) page.tsx hygiene
   - Unused import Image
   - Hero/Banner/etc. could be composed in layout or a single HomeSections
     component if page grows

N) Tailwind class validity / design tokens
   - Non-standard or likely invalid utilities used:
     * gap-112, px-22, pr-42, py-42, mt-50, mt-60, lg:basis-3/11, lg:basis-3/13
   - Standard scale stops at smaller steps; arbitrary values should use bracket
     syntax e.g. gap-[28rem] or extend @theme

   Recommendation: Audit with Tailwind IntelliSense or build; align to design
   tokens in globals.css @theme.

O) AboutUs image layout
   - next/image with fill on parents without explicit min-height on grid cells
     (only overflow-hidden rounded) — risk of zero-height images in some layouts
   - Add aspect-ratio or min-h-* on relative containers

P) Services carousel
   - Custom prev/next outside Carousel but wired via setApi — good pattern
   - Imported CarouselNext/CarouselPrevious unused — remove imports
   - Card overlay uses h1 per slide — should be h2/h3 under page h1

Q) globals.css body override
   - @layer base sets body bg/text; then body { background: var(--foreground);
     color: var(--background); } inverts — intentional dark chrome but easy to
     confuse with theme tokens; document or consolidate
